# Jev 可行性评估

2026-09-28；本次决定为**先评估，暂不调整 Self-RAG 主线**。已核对仓库调用点和 TypeSafe 官方资料，Jev 实际请求数为 0，没有安装 SDK、修改默认模型或上传项目源码。当前进程没有 `TYPESAFE_API_KEY`，未检查其他凭据存储。

## 结论

值得在“给定一条断言和可定位证据，判断支持、矛盾或材料不足”上进行小规模对照。现在没有证据支持把整套 Critic、规划或执行控制交给 Jev，也没有项目内质量、成本或延迟收益数据。前置大小模型路由涉及模型能力标定和失败后的升级成本，工作量大于新增一个分类请求。

当前训练入口 `scripts/run_self_rag_training.py::_train` 使用 `trl.SFTTrainer`，通过 LoRA 与反思 token 行训练进行监督微调。接入 Jev 将增加外部决策模型，不会把这段训练转换为 RLCD；RLCD 是 TypeSafe 对其模型训练方法的命名：[官方介绍](https://docs.typesafe.ai/introduction/machine-learning-primer)。

## 已核对的接口与限制

`POST https://api.typesafe.ai/v1/systemone` 接收 `state`、`model`、`questions`，使用 Bearer API key。Choice 返回选项及概率分布，Score 返回等级评分与分布，Noul 返回真假概率；响应包含实际模型版本和输入/输出 token。相同状态下多个独立问题可合并请求。[API](https://docs.typesafe.ai/api)、[问题类型](https://docs.typesafe.ai/primitives)

官方当前列出 `jev-1.13.0`，输入价格为 $0.042 / 百万 token、输出免费。若一个请求实际计费输入恰为一万 token，按此单价计算是 $0.00042；本项目尚无实际账单或端到端成本。官方标注请求总量 64k token，状态加最长问题 32k；英文效果最好，中文需要单独验证。[模型与价格](https://docs.typesafe.ai/models)

Choice/Score 的 `confidence` 是从分布计算出的统计量，不能直接当作本项目的正确率。官方也明确披露数字、复杂间接推理、无关长上下文、低层表示、对抗内容和生成任务的弱项。这使它更适合判断整理好的源码事实或观察，而不适合直接读大量 IL 后决定运行正确性。[置信度](https://docs.typesafe.ai/confidence)、[已知弱项](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

这是托管接口。官方声明不使用客户请求/响应训练，企业 ZDR 需另行安排；普通请求的数据保留不能按零保留推定。[数据政策入口](https://docs.typesafe.ai/legal)

## 仓库可复用位置

| 位置 | 当前实际职责 | Jev 可评估的增量 |
| --- | --- | --- |
| `evaluation/self_rag_critic.py` 的 `candidates_from_records`、`locate_quote`、`annotation_bindings` | 绑定真实问题、答案与原始上下文，检查引用文本是否存在 | 复用输入与引用定位；只替换语义支持度判断 |
| `evaluation/self_rag_inference.py::infer(..., critic=...)` | 外部 Critic 回调和一次修订 | 已有注入点；先旁路评分保存判断，之后才比较修订策略 |
| `libs/reranker/BaseReranker`、`RerankerFactory` | 配置驱动的候选重排 | 候选相关性评分的后续实验，无需新建检索系统 |
| `planning/request_interpretation.py` | 有限规则识别明确指令，未决语义留给 RequirementProjection | 可评估未决请求类型；明确授权和否定范围仍由现有合同处理 |
| `planning/model_selection.py::ModelPlanningTargetSelector` | 在已有证据中选择修改目标 | 名称中的 model 指模型参与目标选择；它不是轻量/强模型路由器 |
| 原 Graph、ArtifactStore、执行与 Build/Runtime 模块 | 状态、来源、执行与实际验收 | 保持这些职责；Jev 判断作为带来源的观察输入 |

首个接入并非把 Jev 包装成普通文本生成器。现有 Critic schema 还要求生成 `core_claim`、`issue`、`evidence_quotes`，Jev 不生成这些内容。实验可先使用已经标注并能定位的断言与引用；产品使用时，断言提取由代码或通用模型完成，这部分成本要计入总额。

还有一个与供应商无关的职责混用：`existing_local_critic` 用 `select_generator_sample` 的“是否适合进入训练集”结果填充推理期 `accepted`。训练筛选明确排除拒答，而推理中证据不足时拒答可能正确。后续应分开训练筛选和修订决策。为什么要有它：换供应商不能修正错误的验收问题，也不能让正确拒答触发无效重写。

## 项目现有实测给出的依据

现有本地 Critic 的六题校准，在修正两处主机评分口径后符合要求 1/6；原始运行和重评分分别保留。这个小样本说明需要检查判断质量，但尚不能预测 Jev 的表现。

14 道留出题的三种策略已完成，两个 Codex 评审者分别盲化审查各七题的全部策略答案；每题只有一个评审者，属于来源辅助 AI 评审。断言支持度依据生成时可见上下文与题设，完整度和效用审查另可参考题目作者的参考答案；模型反思标签不参与真值判断。

| 策略 | 无证据断言 / 可判定断言 | 完整回答 | 模型调用 | 输入 token | 整轮秒数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定检索 | 10/37（27.0%） | 4/14 | 14 | 16,329 | 159.74 |
| 当前反思 token 微调 | 57/104（54.8%） | 1/14 | 28 | 10,537 | 425.39 |
| 本地外部 Critic + 一次修订 | 11/38（28.9%） | 5/14 | 42 | 59,239 | 802.41 |

“完整回答”包含对不可答题的合理拒答，微调臂的1/14即带事实说明的合理拒答。固定检索和外部 Critic 各有一条歧义断言未进入真假分母。当前小样本微调没有显示质量收益；外部 Critic 的额外调用也没有降低该断言率。生成器是 Qwen3-1.7B，训练含五条审阅过的真实样本与五条合成机制样本；这些结果不能外推至更大训练或其他模型。各策略输出断言数不同，报告是描述性对照。原始数据与可重算汇总在 `e1/self-rag-independent-20260928/blind-review-01/quality-summary-01.json`，SHA-256 `368f87738ad95f6b4f1af1bcdfafdb5596819875117b44a9546ef7aee318523b`。

## 建议的首轮对照，尚未执行

**结果判读与采用决定（上述14题）**：当前小样本微调方案在本轮明显退化，**不进入产品默认路径**；训练和重载成功只完成实现前提。外部Critic以三倍调用取得的结果尚未证明额外成本值得，**暂不推广**，优先核验“训练筛选条件充当推理接受条件”的职责混用。固定检索继续作为这组实验的对照基线，其27.0%无证据断言率也需要改进。为什么要有它：负面结果需要改变采用和投入决定，不能停留在表格，也不能把相对较好写成已经可用。

当前按[交付与评测共同推进](EVALUATION_FIRST_CYCLE.md)安排工作，七项证据责任保留。下一次Self-RAG改动针对输入协议、标签或推理决策的明确失效原因，记录反例及预期变化，再比较质量与总成本；Critic的修订收益还需与“直接重写一次”对照，Jev仍只作方案评估。为什么要有它：新实验应区分原因并支持下一步决定，保留研究目标不等于持续投入已退化的配置。

| 决定 | 为什么要有它 |
| --- | --- |
| 先用公开 RFC 的已有失败样本开发问题措辞；把之后评估的样本按原问题分组，预留整组不调参 | 同一问题的多个答案不能跨组制造独立样本量；现有 14 题用于新方案调优后须标为已暴露 |
| 对相同断言和证据比较代码检查、本地 Critic、Jev；引用不存在先用代码判定 | 避免用新增材料或更好的输入准备冒充 Jev 单独收益 |
| 一个局部判断提供“支持 / 矛盾 / 证据不足”，保留完整分布；明确概率针对给定证据下的支持关系 | 世界知识里的事实真假和当前材料的支持程度是不同问题 |
| 先只记录预测；任何筛选/修订阈值只用开发集确定，再冻结评估 | 防止把未经测量的误判接成新的阻断点 |
| 报告错误接受率、错误拒绝率、各类召回、Brier 分数与分箱样本数、覆盖率，并分开中文/英文和简单/多步样本 | 高 confidence 和总体准确率可能掩盖危险误判；小样本校准不能当保证 |
| 同时记录实际版本、输入哈希、预测、token、含重试延迟与费用；后续修订实验再比较每个成功任务总成本和端到端完成率 | 单次判断便宜不一定减少修订、升级或总耗时 |

这次评估后的优先级：证据支持度对照，其次候选相关性；失败语义归类只处理明确错误码无法解释的部分。前置模型路由待不同模型在实际任务上的能力与成本有数据后再决定。源码一致性、路径权限、预算计数和真实构建/行为验收继续由代码与运行观察负责。为什么要有它：有限语义判断应减少现有工作量，而不是在所有节点增加一次模型请求。
