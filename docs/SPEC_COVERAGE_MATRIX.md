# Spec Coverage Matrix

This file tracks detailed coverage of `DEV_SPEC.md` and its subsystem specs.

It is not a replacement for `docs/ACTIVE_PRODUCT_CONTRACT.md`, `DEV_SPEC.md`,
`EVIDENCE_RAG_MCP_SPEC.md`, `PROJECT_STATE.md`, or `IMPLEMENTATION_QUEUE.md`.
It is the bridge between the full specification and small implementation loops.

Last updated: 2026-07-13

## Status Values

```text
not_started  Spec requirement is recognized but no project-specific implementation exists.
queued       Requirement is assigned to a queue task.
partial      Some implementation exists, but required contract/test/integration is incomplete.
implemented  Code exists with focused tests.
tested       Code exists, focused tests pass, and state/queue documents reference it.
verified     E2E, regression, performance, or real-world evidence proves the behavior.
completed_pending_commit  Working-tree evidence and focused tests exist, but related files are not committed or explicitly accepted as one checkpoint yet.
deferred     Explicitly postponed by V1 scope.
superseded   Replaced by a newer spec decision.
blocked      Cannot proceed until named evidence, dependency, or user input exists.
```

## Coverage Rules

```text
1. A row is not complete because code exists.
2. A row is not complete because an imported RAG skeleton claims it.
3. Controlled fake/local/supplied-output execution is valid only when execution_mode is explicit.
4. Build success never proves runtime behavior.
5. Image caption evidence never proves gameplay success.
6. Dense/vector/multimodal work must not outrank required V1 evidence contracts.
7. Queue tasks must reference this matrix when they close or defer rows.
8. Historical loop records are reconstruction evidence only; current-branch evidence requires the referenced files to exist in this branch and focused tests to be rerun.
9. Optional capability expansion is default-paused unless a registered evaluation result or explicit user decision selects it.
10. `.agents/skills/auto-coder/SKILL.md` is frozen as `SKILL.md.frozen` and is not an active execution authority.
```

## Module Maturity Levels

These levels describe how far a module should be pushed before downstream work
depends on it. They are separate from the status values above.

```text
M0 Contract:
  schema, interface, artifact, failure payload, and forbidden claims are explicit.
M1 Local Deterministic:
  local deterministic, fake, mock, or supplied-output paths can run with explicit execution mode.
M2 Integrated Loop:
  LangGraph, ArtifactStore, trace, tests, blockers, and failure policy consume the module output.
M3 Eval And Dashboard:
  eval cases, metrics, dashboard projection, and claim-boundary tests make behavior inspectable.
```

M3 is not production readiness. Current production-facing task selection is
governed by `docs/ACTIVE_PRODUCT_CONTRACT.md`; the frozen transition document
is historical context only.

## Evidence Provenance Levels

```text
current_branch_verified:
  Referenced files exist in the current branch and focused tests were run after the relevant change.
current_branch_present:
  Referenced files exist in the current branch, but focused tests need to be rerun before stronger claims.
working_tree_evidence:
  Referenced files exist only in the current working tree or include uncommitted control-document updates.
history_restored:
  Detailed record exists in docs/audits/LOOP_HISTORY.md, restored from c43f4ec.
history_only_missing_current_files:
  Historical record names files that are not present in this branch; do not claim current tested coverage until restored or reimplemented.
```

## Trigger Values

Trigger is separate from implementation Status and evidence Provenance. A gap
does not enter the active queue until its exact trigger is satisfied.

```text
active:
  The user selected the work and its dependencies are explicit.
selected_product_failure:
  A concrete product task recorded the named failure.
selected_external_client:
  A concrete external client requires the named interface.
explicit_run_approval:
  The user approved the exact external disclosure, launch, copy, or runtime action for this run.
formal_claim_required:
  A precise promotion-grade, cross-project, or production claim requires the work.
repeated_verified_failure:
  Repeated bound outcomes show that the current manual or deterministic path is insufficient.
none_satisfied:
  No current product trigger exists; the row remains outside the queue.
```
